CONCLUSIONES Y HALLAZGOS

1. Se ejecutó una prueba de carga sobre el servicio de autenticación utilizando Apache JMeter, configurando un throughput objetivo de 20 transacciones por segundo.

2. La parametrización mediante archivo CSV permitió simular múltiples usuarios concurrentes, mejorando la representatividad del escenario de prueba.

3. El sistema presentó un tiempo de respuesta promedio de 633 ms, cumpliendo con el requisito establecido de máximo 1.5 segundos.

4. La tasa de error fue de 0.62%, valor que se encuentra dentro del límite aceptable (<3%), indicando estabilidad en las respuestas del servicio.

5. El throughput alcanzado fue de 18.6 TPS, valor cercano al objetivo planteado. Esta ligera variación puede atribuirse a factores como latencia de red o capacidad del entorno de prueba.

6. No se evidenciaron errores críticos del sistema durante la ejecución, lo cual indica que el servicio es capaz de soportar la carga configurada bajo condiciones normales.

RECOMENDACIONES

* Incrementar ligeramente el número de hilos para asegurar el cumplimiento de los 20 TPS.
* Ejecutar pruebas en un entorno controlado para reducir la variabilidad del throughput.
* Implementar monitoreo de recursos (CPU, memoria) para complementar el análisis de rendimiento.
* Realizar pruebas progresivas de carga para identificar el punto de saturación del sistema.

En conclusión, el sistema cumple con los criterios de rendimiento establecidos, mostrando estabilidad y tiempos de respuesta adecuados bajo carga concurrente.
